# Final Project Upgrade Plan

This document separates practical upgrades from ceremony. The goal is to turn the completed notebook into a polished project demo without obscuring the academic requirements.

## Current State

The project is currently a reproducible notebook deliverable:

- downloads the assigned Amazon Gift Cards datasets
- performs Phase 1 and Phase 2 EDA
- trains lexicon and machine learning sentiment models
- compares models on shared test data
- implements a sentiment-enhanced recommender experiment
- runs local Hugging Face summarization and response-generation tasks

This is enough for the course code requirement. It is not yet a product-style app.

## Recommended Upgrade Path

### 1. FastAPI Backend

Build a small backend around saved results and trained artifacts.

Endpoints:

| Endpoint | Purpose |
|----------|---------|
| `GET /health` | deployment health check |
| `GET /metrics/summary` | return model metrics and dataset summary |
| `POST /sentiment/predict` | classify a submitted review using selected model |
| `POST /recommend/enhance` | return baseline and sentiment-enhanced score |
| `GET /examples/summaries` | return the 10 LLM summary examples |
| `POST /llm/respond` | draft a service-response style answer |

Keep the backend read-mostly. It should not retrain models on every request.

### 2. SvelteKit Frontend

Build a presentation-grade UI, not a generic dashboard.

Recommended screens:

1. **Dataset Reality** - show the heavy positive skew and why accuracy alone is misleading.
2. **Model Arena** - compare VADER, SentiWordNet, Logistic Regression, and Naive Bayes.
3. **Try a Review** - paste a review and see predicted sentiment from multiple models.
4. **Recommendation Lab** - adjust the sentiment blend weight and observe score changes.
5. **LLM Desk** - show long-review summaries and the service-response example.

This gives the project "pizzazz" while staying grounded in the assignment.

### 3. Model Artifact Layer

Persist artifacts generated by the notebook:

- TF-IDF vectorizer
- Logistic Regression model
- Naive Bayes model
- metrics JSON
- selected LLM examples
- recommender item-score tables

Suggested layout:

```text
Final Project/
├── app/
│   ├── backend/
│   └── frontend/
├── artifacts/
│   ├── models/
│   ├── metrics/
│   └── examples/
└── project262_gr5_ph2_code.ipynb
```

Do not commit large raw data or heavyweight model downloads.

### 4. LangGraph and RAG, Only If Useful

The clean non-ceremonial agent use case is an **Ask the Project** assistant.

It should answer questions using retrieved evidence from:

- project README
- report sections
- notebook metric outputs
- selected review examples
- recommender paper notes

Good questions:

- "Why is macro-F1 lower than accuracy?"
- "Why did the sentiment-enhanced recommender perform worse?"
- "Which chart should go on the presentation slide about imbalance?"
- "What evidence supports choosing TF-IDF?"

Recommended local platform fit:

| Platform component | Role |
|--------------------|------|
| vLLM | OpenAI-compatible chat completion backend |
| TEI | embeddings for report/notebook chunks |
| Qdrant | vector store for project evidence |
| LangGraph | controlled retrieval and answer workflow |
| Postgres | optional durable chat/session state |
| Grafana/Prometheus | app and agent request monitoring |

Avoid adding LangGraph if it only wraps a single prompt. That would be ceremony.

### 5. Kubernetes Deployment

Once backend/frontend exist:

- package backend and frontend images to GHCR
- create Kubernetes manifests or HelmRelease resources
- expose internally first
- add basic auth or platform auth before public tunneling
- add Prometheus scrape annotations for the API

Minimal runtime:

```text
SvelteKit frontend -> FastAPI backend -> local artifacts
                                  -> vLLM/TEI/Qdrant only for optional RAG
```

## Suggested Priority

1. Write the final report and slides.
2. Add saved artifacts and FastAPI endpoints.
3. Add SvelteKit UI.
4. Add Docker and local run docs.
5. Add Kubernetes manifests.
6. Add RAG assistant only after the app already communicates the core results well.

The strongest demo is not the most complex stack. The strongest demo is one where every extra component explains or exposes a project result better than the notebook alone.
